# 帧格式

> 中文 | [English](../../en/communication/framing.md) · [索引](../index.md) · [首页](../../../README.md)

两条管道使用同一种帧格式：**4 字节小端无符号长度 + UTF-8 TOML 正文**。

```text
+----------------------+---------------------------------------+
| uint32 little-endian | TOML 正文（N 字节，UTF-8，无 BOM）    |
|        N             |                                       |
+----------------------+---------------------------------------+
```

| 字段 | 长度 | 说明 |
| --- | --- | --- |
| 长度 | 4 字节 | 无符号 32 位小端整数，只表示正文长度，不含这 4 字节 |
| 正文 | N 字节 | 恰好一个 TOML 1.0 文档；根必须是表（table） |

## 规则

1. `1 <= N <= 1,048,576`（1 MiB）。空帧或超过 1 MiB 都是协议错误。
2. 正文必须是合法 UTF-8，不带 BOM，不带结尾 NUL。
3. 正文是一个 TOML 文档，不是“每行一个消息”。
4. 一帧只承载一条消息；TOML 内部可以多行、带注释或嵌套表。
5. 发送方必须先完整写入 4 字节长度，再写正文；接收方必须处理长度头或正文被拆成多次读写的情况。
6. 一次写入可以包含多个帧；接收方必须按长度循环解析。
7. stub 转发时必须保持正文原始字节不变，不得重新序列化 TOML。
8. 长度头可以重新生成，但数值必须与正文长度一致。
9. 不支持用换行、NUL 或其他分隔符代替长度头。
10. 读取必须有上限和超时；单方向缓存不得超过 64 帧或 4 MiB。

## 示例

正文为 `type = "startInstall"`（21 字节，不含换行）时，帧开头是：

```text
15 00 00 00
```

随后是 21 字节 UTF-8 正文。

## 非法帧

以下任一情况都是致命协议错误，stub 必须结束整个会话：

- 长度小于 1 或大于 1 MiB；
- 正文不是合法 UTF-8；
- 正文不是合法 TOML 1.0；
- TOML 根不是表；
- 缺少字符串类型的 `type`；
- 帧被截断或管道在帧中间关闭。

消息字段错误（例如 `value` 类型不对）不是帧错误，按 [消息](messages.md) 和 [错误处理](errors.md) 处理。
