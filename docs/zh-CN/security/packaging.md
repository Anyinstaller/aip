# 打包、签名与完整性

> 中文 | [English](../../en/security/packaging.md) · [索引](../index.md) · [首页](../../../README.md)

本页规定打包器必须做什么、`foo.exe` 在发布前必须满足什么。所有条目都是强制项（MUST）。

## 打包器职责

打包器接收以下输入：

```text
build\
├─ stub.exe
├─ client.exe
├─ backend.exe
├─ config.toml        # 源配置，图片路径可以是本机路径
├─ payload.zip
└─ assets\            # 可选
```

输出只有一个 `foo.exe`。打包器必须：

1. 校验源 `config.toml`：语法、协议号、必填字段、`name` 长度和字符。
2. 校验 `payload.zip`：合法 ZIP、条目数量、总大小、压缩比、路径合法。
3. 解析 `icon` / `background` 的源图片路径：必须存在、可解码，并满足大小和像素限制。
4. 把图片复制到包内 `assets/`，把打包后配置中的路径重写为包内相对路径。
5. 生成组件清单，记录每个内嵌文件的逻辑名、SHA-256、大小和包内相对路径。
6. 判断客户端覆盖安装时是否需要保留用户数据——AIP 不规定，由 backend 自行实现。
7. 把 stub 作为 PE 主体，把其余组件写入资源、覆盖数据或内嵌归档。
8. 生成 `foo.exe`，并做一次自解包回读测试：按运行时同样规则解析并校验每个组件。
9. 对 `foo.exe` 签名并加盖 RFC 3161 时间戳。
10. 签名后再次校验签名和清单，确认发布物可被 stub 接受。

任何一步失败，打包器必须退出非零状态，不得留下半成品 `foo.exe`。

## 组件清单

清单必须至少包含：

| 字段 | 说明 |
| --- | --- |
| 逻辑名 | `stub.exe`、`client.exe`、`backend.exe`、`config.toml`、`payload.zip`、资源路径 |
| 包内相对路径 | 释放到会话目录时的目标路径 |
| 大小 | 字节数 |
| SHA-256 | 组件原始字节的哈希 |
| 类型 | 可执行文件、配置文件、归档、资源 |

清单本身必须在 `foo.exe` 的签名覆盖范围内。stub 必须在释放前后都校验哈希；任一不匹配必须中止。

## 签名

1. `foo.exe` 必须使用 Authenticode 签名。
2. 必须加盖时间戳，使证书过期后签名仍然有效。
3. 必须使用受信任的公共代码签名证书。EV 证书能减少 SmartScreen 警告，但不能替代签名和完整性校验。
4. 签名必须在打包完成后进行，签名不能覆盖清单中的哈希校验。
5. 不得分发未签名、测试签名或使用自签名根证书的发布包。
6. 签名私钥不得存放在构建机可被安装器写入的路径中。

## 完整性

1. stub 启动时必须用 `WinVerifyTrust` 校验自身签名，并检查吊销状态。
2. stub 必须校验清单签名和每个组件的 SHA-256。
3. 释放到会话目录后，必须再次校验哈希，防止释放过程被替换。
4. 校验失败必须 fail closed：不启动 client/backend，不执行安装，显示可读错误。
5. 不得使用“忽略证书错误”“仅警告”之类的选项。
6. 不得从网络下载补充组件或更新清单。

## 单文件约束

1. 发布目录中只能有 `foo.exe`；不得附带 DLL、配置文件、资源文件、`*.pdb` 或安装脚本。
2. 运行时需要的所有内容都必须内嵌，包括 VC 运行库、.NET 运行时依赖、图标和背景。
3. 不得依赖系统上预装的任意版本运行库；如果依赖，必须由打包器内嵌并在清单中记录。
4. `foo.exe` 不得在运行时修改自身或向自身旁边写文件。
5. 安装包不得要求用户先解压；也不得生成临时 sidecar 文件供外部程序使用。

## 资源处理

1. 源图片必须是本地文件；打包器不得从网络 URL 获取资源。
2. 打包器必须拒绝 SVG、HTML、可执行文件伪装成图片等非预期格式。
3. 打包器必须把图片解码后重新编码为受支持格式，去除元数据和附加数据块。
4. 包内资源路径必须使用正斜杠分隔的相对路径，例如 `assets/background.avif`。
5. 包内路径不得包含 `..`、盘符、UNC、设备前缀、ADS 或控制字符。
6. 打包后配置中的每个资源路径都必须能在清单中找到对应组件。

## payload.zip

1. 必须是合法 ZIP，使用受支持的压缩算法（store 或 deflate）。
2. 不得包含加密条目、符号链接、硬链接或重解析点。
3. 不得包含可执行安装脚本作为“安装逻辑”；安装逻辑只允许在 backend 中。
4. 条目路径必须是相对的，不含 `..`、盘符、UNC、ADS、设备名和结尾点/空格。
5. 打包器必须统计条目数、总解压大小、单文件大小和压缩比，并与运行时限制一致。
6. 打包器必须拒绝空 ZIP（0 个条目）。

## 发布前检查清单

发布前必须逐项确认：

- [ ] `foo.exe` 是目录中唯一文件。
- [ ] `foo.exe` 已签名并带时间戳，`signtool verify /pa /all` 通过。
- [ ] 组件清单覆盖所有内嵌文件，SHA-256 正确。
- [ ] 打包后 `config.toml` 中没有本机绝对路径。
- [ ] `protocol = 1`，`name` 和 `[defaults]` 完整。
- [ ] 所有图片可解码，且未超过大小和像素限制。
- [ ] `payload.zip` 通过路径穿越、ZIP 炸弹和设备名检查。
- [ ] 在一个干净的用户账户上测试完整安装、取消和失败回滚。
- [ ] 在无网络环境下测试，确认没有下载行为。
- [ ] 用 Process Monitor 确认没有读写包外资源、安装目录之外的路径。

强制运行时安全要求见 [强制安全要求](requirements.md)。
