# 强制安全要求

> 中文 | [English](../../en/security/requirements.md) · [索引](../index.md) · [首页](../../../README.md)

AIP v1 **没有可选安全项**。本页所有条目都是 **必须**（MUST）。任何一条不满足，该实现就不符合 AIP v1，不得作为发布包分发。

## 威胁模型

必须假设以下威胁存在：

- 本机其他进程尝试抢占或伪造命名管道；
- 攻击者篡改 `foo.exe` 或其中内嵌的组件；
- 恶意 `payload.zip` 使用路径穿越、ZIP 炸弹、ADS、符号链接或设备名；
- 恶意配置让安装写入系统目录、读取包外文件或创建恶意快捷方式；
- 临时目录被其他进程读写或替换；
- 安装器被诱导以高权限执行非预期操作；
- DLL 搜索顺序劫持、未初始化输入、无界内存分配。

## 1. 进程与权限

1. stub、client、backend 必须运行在同一用户、同一登录会话、同一完整性级别。
2. 禁止 stub 以中完整性启动、再单独提升 backend；禁止混合完整性管道。需要管理员权限时，必须由 `foo.exe` 的清单整体声明 `requireAdministrator`；否则必须声明 `asInvoker`。
3. stub 必须创建 Job Object，设置 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`，并把 client 和 backend 都加入。stub 异常退出时，子进程必须被系统杀死。
4. stub 必须以 `bInheritHandles = FALSE` 启动子进程；管道句柄、进程句柄和其他内核句柄不得继承。
5. client 和 backend 必须从私有会话目录启动。stub 必须验证实际映像路径位于该目录内，且不是重解析点。
6. stub 不得对 client/backend 调用 `ImpersonateNamedPipeClient`，不得启用 `SeDebugPrivilege`，不得请求与任务无关的权限。
7. 所有安全校验失败必须 fail closed：结束子进程、删除会话目录、不执行安装、不创建快捷方式。
8. 任何组件都不得执行来自管道、配置或 payload 的 shell 命令。

## 2. 命名管道

1. 管道必须使用仅允许当前用户 SID 访问的 DACL；不得允许 Everyone、Users、匿名或远程主体。
2. 管道必须设置 `PIPE_REJECT_REMOTE_CLIENTS`。
3. 管道名必须包含至少 128 位随机会话 ID，不得使用固定名称或可预测名称。
4. 每条管道只创建一个实例，只接受一个连接；连接建立后必须立即关闭监听端。
5. stub 必须用 `GetNamedPipeClientProcessId` 获取连接方 PID，并与自己启动的子进程 PID 比较；必须用 `GetNamedPipeClientSessionId` 校验登录会话；必须校验连接进程令牌的用户 SID 与当前用户一致。任一不匹配必须断开并中止。
6. client 必须以 `SECURITY_SQOS_PRESENT | SECURITY_IDENTIFICATION` 打开管道，限制服务端模拟。
7. 管道必须以字节模式工作（`PIPE_TYPE_BYTE | PIPE_READMODE_BYTE | PIPE_WAIT`）。
8. 所有管道 I/O 必须使用 overlapped I/O 或等效机制，并设置超时/取消；不得无限阻塞。
9. 单帧最大 1 MiB；每个方向最多缓存 64 帧或 4 MiB。超过限制必须中止会话。
10. stub 只解析帧的 `type` 以识别 `readyToExit`；不得执行消息内容，不得根据消息内容启动新进程。

## 3. 会话目录与释放

1. 会话目录必须创建在 `%LOCALAPPDATA%\Anyinstaller\Sessions\<随机ID>`；不得使用 `%TEMP%` 根目录、公共目录或可预测路径。
2. 目录必须使用仅当前用户和 SYSTEM 可访问的 DACL，且不得继承父目录的宽松 ACE。
3. 创建目录必须使用 `CREATE_NEW` 语义；必须拒绝已存在的路径、重解析点和符号链接。
4. 释放组件后，必须逐个校验 SHA-256 与签名清单一致；任一不匹配必须中止。
5. 释放完成后，会话目录必须设置为只读；client/backend 只能读取，不得写入。
6. stub 必须在正常退出、异常退出和强制结束路径上都删除会话目录；无法删除的锁定文件必须在重启后清理。
7. 不得把 `config.toml`、`payload.zip` 或任何资源释放到用户安装目录或桌面等持久位置。

## 4. 安装位置

1. `installLocation` 展开 `%VAR%` 后必须是本地盘符绝对路径（例如 `D:\Apps\Example`）。
2. 必须拒绝：UNC/网络路径、设备路径（`\\.\`、`\\?\`）、相对路径、盘符相对路径（`C:foo`）、包含 `..` 的路径、NTFS ADS、空字符串、包含 NUL 的字符串。
3. 必须用 `GetFullPathNameW` 或等效 API 规范化，并再次校验结果。
4. 必须拒绝盘符根目录、`%SystemRoot%` 及其子目录、`%ProgramFiles%` / `%ProgramFiles(x86)%` 根目录、`%ProgramData%` 根目录、用户配置目录根、桌面根、开始菜单根和会话目录。
5. 必须检查从卷根到目标的每一级路径，拒绝重解析点、符号链接和 junction，防止路径重定向。
6. 安装必须先在目标父目录下创建随机命名的私有暂存目录，使用仅当前用户和 SYSTEM 可访问的 DACL；解压、校验完成后再提交。
7. 提交失败时必须删除暂存目录；不得把文件写到安装位置、开始菜单或桌面之外的路径。
8. 不得在安装过程中执行 payload 中的任何程序、脚本或 DLL。

## 5. 快捷方式

1. 必须使用 `SHGetKnownFolderPath` 获取当前用户的 `FOLDERID_Programs` 和 `FOLDERID_Desktop`；不得仅依赖环境变量拼接路径。
2. 必须使用 `IShellLinkW` + `IPersistFile` 创建 `.lnk`，不得手写二进制快捷方式文件。
3. 快捷方式目标必须是安装目录内已存在、非重解析点的文件；规范化后必须仍在安装目录内。
4. 快捷方式名称必须来自经过文件名净化的 `name`，长度受限，不得包含路径分隔符。
5. 快捷方式参数和工作目录必须由 backend 固定生成，不得从配置或管道接受任意命令行。
6. `createStartMenuFolder = false` / `createDesktopShortcut = false` 只表示不创建，不得删除用户已有文件。
7. 只有 payload 成功写入且校验通过后才允许创建快捷方式；安装失败时不得留下指向不存在目标的快捷方式。

## 6. ZIP 解压

1. 只接受合法 ZIP；必须校验每个条目的 CRC 和实际解压大小。
2. 必须拒绝：绝对路径、盘符路径、UNC、`..`、NTFS ADS、设备名（`CON`、`NUL`、`COM1` 等）、结尾点/空格、空文件名、超长路径。
3. 必须拒绝符号链接、重解析点、加密条目和不支持的压缩算法。
4. 限制：最多 100,000 个条目；解压后总大小不超过 8 GiB；单文件不超过 4 GiB；压缩比不超过 100:1；单条路径不超过 32,767 个 UTF-16 代码单元。
5. 每个条目在写入前必须规范化，并确认最终真实路径位于暂存目录内；必须拒绝重解析点。
6. 解压过程中不得覆盖暂存目录之外的任何文件；不得继承 ZIP 中的危险文件属性。
7. 解压完成后必须再次检查条目数量、总大小和路径；任何异常都必须中止并清理。

## 7. 配置与资源

1. `config.toml` 最大 64 KiB；必须是 UTF-8 无 BOM；必须严格校验已知字段类型和长度。
2. 打包后配置中的 `icon` / `background` 图片路径必须是包内相对路径；必须拒绝绝对路径、盘符、UNC、设备前缀、`..`、ADS 和重解析点。
3. 资源必须从会话包根目录解析，解析后的真实路径必须仍在包根目录内；不得读取包外文件。
4. 单个图标/背景文件最大 64 MiB；解码后最大 256 百万像素，单边最大 16,384 像素。
5. 打包器必须把源配置中的本机图片路径嵌入 `foo.exe` 并重写为包内路径；打包后配置不得残留本机绝对路径。
6. 运行时发现非法资源路径时，必须回退默认图标或白色背景并记录错误；不得尝试读取包外路径。
7. 配置中的 `%VAR%` 展开必须使用当前进程环境；无法展开的变量必须视为错误，不得保留字面量继续安装。

## 8. 网络与执行

1. AIP 通讯只允许本机命名管道；不得建立网络监听、网络连接或远程管道。
2. 安装期间 stub/client/backend 不得下载、执行或更新远程内容；操作系统签名吊销检查除外。
3. 不得通过 `cmd.exe`、PowerShell、`ShellExecute` 或未加约束的 `CreateProcess` 执行字符串命令。
4. 启动 client/backend 必须使用 `CreateProcessW`，显式指定映像路径、当前目录和参数；不得依赖当前目录搜索。
5. 不得从用户可写目录加载 DLL；必须使用安全 DLL 搜索策略（例如 `SetDefaultDllDirectories(LOAD_LIBRARY_SEARCH_SYSTEM32)`）。

## 9. 二进制加固

1. 所有原生组件必须启用 ASLR（`/DYNAMICBASE`）、DEP（`/NXCOMPAT`）、CFG（`/guard:cf`）、栈保护（`/GS`）和高熵 VA（`/HIGHENTROPYVA`）。
2. 必须使用安全的字符串和内存 API，所有来自管道、配置、ZIP 和文件系统的长度都必须校验。
3. 必须避免当前目录 DLL 搜索、`LoadLibrary` 加载用户路径、未加引号的路径和可预测的临时文件名。
4. 发布版 `foo.exe` 必须使用 Authenticode 签名并加盖时间戳；不得分发未签名包。
5. 依赖库必须来自可信来源，并保持安全更新；不得捆绑已知存在可利用漏洞的版本。

## 10. 失败、日志与合规

1. 任何安全校验失败必须立即中止，不得继续安装、不得创建快捷方式、不得回退到不安全路径。
2. 错误信息必须是 UTF-8 文本，不包含 NUL；不得输出密钥、令牌或完整凭据。
3. 日志不得写入安装目录或包内资源；如需记录日志，必须写入会话目录或用户日志目录，并在清理时删除。
4. 本页所有条目都是 AIP v1 合规的必要条件。实现不得通过配置、命令行开关或环境变量关闭这些要求。

打包、签名和完整性校验的强制要求见 [打包、签名与完整性](packaging.md)。
