# 版本与兼容性

> 中文 | [English](../en/versioning.md) · [索引](index.md) · [首页](../../README.md)

## 版本标识

| 项目 | 当前值 |
| --- | --- |
| 规范名称 | Anyinstaller Protocol（AIP） |
| 规范版本 | AIP v1 |
| 协议号 | `1` |
| 管道帧格式 | 4 字节小端长度 + UTF-8 TOML |
| 平台 | Windows 10/11 |

`config.toml` 中的 `protocol = 1` 是唯一的机器可读版本标识。stub 必须拒绝无法识别的协议号，不得猜测或降级。

## 兼容性规则

以下修改**不提升**协议号，只需保持向后兼容：

- 增加可选配置字段；
- 增加新的消息类型；
- 增加新的背景特殊值（前提是旧实现会把它当作无效图片路径并回退白色）；
- 增加新的可选资源文件；
- 修正文档错误，不改变线上行为。

以下修改**必须提升**协议号：

- 修改帧格式、长度字段或编码；
- 修改已有消息的必填字段、类型或语义；
- 修改“后发有效”或“只发送一次”的规则；
- 修改启动参数；
- 修改包结构或资源路径解析规则；
- 修改安全要求，使旧实现不再合规；
- 删除或重命名已有消息、配置字段或特殊背景值。

## 向前兼容

1. 接收方必须忽略未知字段和未知消息类型。
2. stub 必须转发除 `readyToExit` 以外的未知消息。
3. client/backend 不得因为遇到未知可选字段而崩溃或拒绝运行。
4. 未知的 `background` 特殊值按图片路径处理；无法解析时回退白色。

## 协议号不匹配

- `protocol` 缺失、不是整数或不是 `1`：stub 显示错误并退出，不释放组件，不启动子进程。
- 未来协议号（例如 `2`）：AIP v1 的 stub 必须拒绝，不得尝试兼容。
- 打包器必须写入其支持的协议号；不得写入“最新版”等非数字值。

## 规范变更流程

1. 修改本仓库文档。
2. 判断是否需要提升协议号。
3. 如果需要提升，同时更新所有受影响的例子和 `examples/`。
4. 在提交信息中说明兼容性影响。
5. 旧协议号对应的文档必须保留在版本历史中，不能原地覆盖。

## 应用版本

AIP 不规定应用版本号。`name` 是显示名称，不是版本。backend 可以自行决定如何在安装目录、快捷方式或注册表中记录应用版本，但这不属于 AIP。
